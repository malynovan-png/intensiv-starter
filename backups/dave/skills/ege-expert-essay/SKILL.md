# ЕГЭ Эксперт_Essay

## Назначение навыка

Навык предназначен для строгой, воспроизводимой проверки задания 38 ЕГЭ по английскому языку — письменного высказывания с элементами рассуждения на основе таблицы или диаграммы.

Навык оценивает работу по критериям:

- К1 — решение коммуникативной задачи: 0–3;
- К2 — организация текста: 0–3;
- К3 — лексика: 0–3;
- К4 — грамматика: 0–3;
- К5 — орфография и пунктуация: 0–2.

Максимум: **14 баллов**.

Этот skill отвечает именно за ПРОВЕРКУ.

Он не определяет личность агента, тон характера, общие ценности Hermes и другие глобальные правила.

---

# 1. ГЛАВНЫЙ ПРИНЦИП

Проверяется только оригинальный текст ученика.

До выставления баллов запрещено:

- исправлять текст;
- переписывать предложения;
- добавлять пропущенные слова;
- исправлять проценты;
- исправлять формулировки;
- мысленно заменять ошибочный вариант правильным;
- додумывать, что ученик «хотел сказать»;
- считать исправленную агентом конструкцию частью исходного ответа.

Всегда оценивай:

> Что ученик фактически написал?

а не:

> Что ученик, вероятно, хотел написать?

Если смысл можно получить только путём догадки, не восстанавливай его автоматически в пользу ученика.

---

# 2. НУЛЕВОЕ ПРАВИЛО: НИКОГДА НЕ ПРИДУМЫВАЙ ОШИБКУ

Каждая ошибка, указанная в проверке, должна существовать в оригинальном тексте.

Перед фиксацией ошибки:

1. Найди точную цитату.
2. Убедись, что она действительно есть в тексте.
3. Определи тип ошибки.
4. Только затем занеси её в журнал.

Нельзя писать:

> «Нет запятой после However»

если ученик написал:

> However, ...

Нельзя писать:

> «Использована стяжённая форма»

если contractions в тексте отсутствуют.

Нельзя приводить пример ошибки из другого эссе.

Нельзя оценивать слово, которого на фотографии не видно.

### Правило доказательства

Каждая ошибка должна иметь структуру:

```text
ОРИГИНАЛ → ТИП ОШИБКИ → ОБЪЯСНЕНИЕ
```

Например:

```text
must to take
→ К4, грамматика
→ после modal verb must используется infinitive без to.
```

Если агент не может привести точный фрагмент оригинала, ошибка не засчитывается.

---

# 3. НЕ НАКАЗЫВАТЬ «ДЛЯ НАДЁЖНОСТИ»

Запрещено:

> «По шкале получается 2, но поставлю 1 для строгости».

Запрещено:

> «Эксперт, наверное, мог бы снять ещё балл».

Запрещено:

> «Оставим более консервативную оценку».

Баллы выводятся только из правил.

Если по критерию получается 2 балла, ставь 2.

Если конструкция допустима в современном английском, не объявляй её ошибкой просто потому, что существует более красивый вариант.

---

# 4. НЕ ШТРАФОВАТЬ ОДНУ ОШИБКУ ДВАЖДЫ

Перед классификацией каждой ошибки определить её первичную природу.

Использовать дерево:

```text
1. Ошибка искажает содержание задания, данные или выполнение пункта плана?
→ К1.

2. Ошибка касается логики, абзацев, связности, средства логической связи?
→ К2.

3. Ошибка касается значения слова, выбора слова или сочетаемости?
→ К3.

4. Ошибка касается грамматической формы или конструкции?
→ К4.

5. Всё языковое содержание правильно, но нарушено написание или пунктуация?
→ К5.
```

Одна причина не должна автоматически создавать две ошибки.

---

# 5. ВНУТРЕННИЙ ЖУРНАЛ ОШИБОК

Перед выставлением баллов Hermes должен внутренне создать error ledger.

Пример:

```yaml
errors:

  - id: G1
    quote: "must to take"
    criterion: K4
    type: modal_infinitive
    rule: "must + bare infinitive"
    instances: 1
    counted_errors: 1

  - id: G2
    quote:
      - "he choose"
      - "she prefer"
      - "it show"
    criterion: K4
    type: third_person_s
    rule: "Present Simple third-person singular"
    instances: 3
    counted_errors: 1

  - id: L1
    quote: "do the bed"
    criterion: K3
    type: collocation
    counted_errors: 1
```

Пользователю YAML показывать не обязательно.

Его задача — не дать агенту:

- считать одно и то же правило несколько раз;
- потерять ошибку;
- сначала назвать 3 ошибки, а потом выставить балл как за 1;
- классифицировать один фрагмент одновременно в К3 и К4 без основания.

# 6. РЕЖИМЫ ПРОВЕРКИ

Навык поддерживает три режима проверки.

## FULL_CHECK

Используется, когда доступны:

- исходное задание;
- таблица / диаграмма;
- полный текст ученика.

Можно выставлять окончательные К1–К5 и итог /14.

## ESSAY_WITHOUT_TASK

Есть эссе, но нет исходного задания.

Можно:

- полностью считать объём;
- проверять К2;
- проверять К3;
- проверять К4;
- проверять К5;
- анализировать видимую структуру.

Нельзя:

- подтверждать правильность процентов;
- утверждать, что группа респондентов названа верно;
- подтверждать правильность options;
- окончательно оценивать соответствие проблемы вопросу;
- окончательно оценивать заключение;
- выставлять окончательный К1 как будто задание известно.

К1 обозначить:

> предварительная оценка — требуется исходное задание для окончательной проверки.

Никогда не реконструировать таблицу из головы.

## FRAGMENT_CHECK

Если пользователь прислал только:

- один абзац;
- два последних абзаца;
- часть фотографии;
- начало эссе;

проверять только данный фрагмент.

Не выставлять итог /14.

Допустимо написать:

> Полный итог К1–К5 по этому фрагменту выставить нельзя, поскольку отсутствует часть работы.

После этого:

- разобрать ошибки;
- определить, какой аспект плана реализован;
- объяснить возможное влияние на критерий.

---

# 7. РАБОТА С ФОТО И СКАНАМИ

Если текст поступает с фотографии:

1. Сначала буквально транскрибировать.
2. Не включать autocorrect.
3. Не исправлять странные формы.
4. Сохранять исходные:
   - артикли;
   - окончания;
   - пунктуацию;
   - кавычки;
   - capitalisation;
   - ошибки написания.
5. Неразборчивое место обозначать:
   `[неразборчиво]`.

Если чтение слова неуверенное и от него зависит балл:

- не угадывать;
- не считать ошибкой уверенно;
- пометить неопределённость.

Если прислано несколько изображений:

- объединять только те части, которые очевидно относятся к одной работе;
- сохранять исходный порядок;
- не смешивать два разных эссе.

# 8. ЭТАП 1 — ОБЪЁМ

Подсчёт слов проводится ВСЕГДА первым.

До подсчёта слов не выставлять К1–К5.

## Норма

Заявленный объём:

**200–250 слов.**

Допуск ±10%:

**180–275 слов.**

### 179 слов и меньше

Работа не проверяется.

```text
К1 = 0
К2 = 0
К3 = 0
К4 = 0
К5 = 0

ИТОГО: 0/14
```

Можно дать учебный комментарий, но нельзя выставлять ненулевые критерии.

### 180–275

Проверяется весь текст.

### 276+

Проверяется только начало работы в пределах первых 250 слов.

Всё после границы проверки:

- не используется для К1;
- не используется для К2;
- не используется для К3;
- не используется для К4;
- не используется для К5.

Обозначить:

```text
Слово 250 — граница проверки.
Всё дальнейшее не учитывается.
```

Если исключительно для завершения практически законченного предложения нужны ещё 1–2 слова, HOUSE RULE разрешает технически дочитать их.

Это не означает, что разрешено учитывать ещё одно целое предложение или абзац.

# 9. КАК СЧИТАТЬ СЛОВА

В режиме полной проверки показать пословную нумерацию.

Пример:

```text
1. I
2. am
3. doing
4. a
5. project
...
```

После:

```text
Итого: 236 слов.
Работа находится в допустимом диапазоне 180–275 слов.
Проверяется полностью.
```

## Отдельные правила

```text
37% = 1 слово
37 percent = 2 слова
37 per cent = 3 слова
```

```text
well-known = 1 слово
English-speaking = 1 слово
```

```text
don't = 1 слово
I'm = 1 слово
```

```text
the option = 2 слова
```

Номер задания:

```text
38.1
38.2
```

не считать словом эссе.

Название задания или служебную маркировку бланка не считать частью ответа.

# 10. ПРОВЕРКА НА ПРОДУКТИВНОСТЬ

Если доступен опубликованный источник для сравнения:

- текстуальное совпадение длиной 10 и более слов учитывать как совпадающий фрагмент;
- суммировать совпадения;
- если более 30% ответа имеет непродуктивный характер:

```text
К1 = 0
ИТОГО = 0/14
```

Если у Hermes нет базы опубликованных ответов:

НЕ ПИСАТЬ:

> «Работа продуктивна».

Писать:

> Проверка на текстуальные совпадения с опубликованными источниками не проводилась.

# 11. ЭТАП 2 — К1

# К1 — Решение коммуникативной задачи

Максимум: **3 балла**.

Проверяется содержание, а не качество грамматики.

Нужно рассмотреть:

1. вступление / проект;
2. факты;
3. сравнение + комментарий;
4. проблема + решение;
5. мнение + объяснение;
6. нейтральный стиль.

Для аспектов 1–5 использовать:

```text
FULL — раскрыт полно и точно
PARTIAL — раскрыт неполно / неточно
MISSING — не раскрыт
```

# 12. К1 — АСПЕКТ 1: ВСТУПЛЕНИЕ

Проверить:

✔️ есть проект;

✔️ тема соответствует заданию;

✔️ понятно, что автор нашёл результаты опроса;

✔️ источник назван как survey/results/data;

✔️ table или pie chart указаны в соответствии с заданием;

✔️ страна / группа респондентов не искажены;

✔️ коммуникативная ситуация соответствует заданию.

Для образцовой структуры приветствуется:

```text
I am doing a project on ...
I have found the results of a survey ...
The results are presented in the form of a table / pie chart.
I am going to comment on the data and give my opinion ...
```

При проверке НЕ требовать дословного шаблона.

Например:

```text
My project is designed to explore...
```

может быть полностью допустимым началом.

Не снижать только за отсутствие фразы `I am doing a project`, если смысл проекта передан корректно.

---

# 13. К1 — АСПЕКТ 2: ФАКТЫ

Ученик должен выбрать **2–3 факта** из таблицы/диаграммы.

HOUSE RECOMMENDATION для обучения — ровно 2.

Но при проверке:

- 2 факта допустимы;
- 3 факта допустимы.

Проверить каждое:

✔️ option существует;

✔️ процент правильный;

✔️ группа правильная;

✔️ смысл вопроса опроса передан правильно;

✔️ информация действительно взята из задания.

Нельзя придумывать:

- новую option;
- новый процент;
- новую группу;
- новый ответ респондентов.

---

# 14. ФАКТИЧЕСКИЕ ОШИБКИ = К1

Любая ошибка в данных относится к К1.

Пример:

Дано:

```text
Reading — 37%
```

Ученик:

```text
Reading — 73%
```

→ К1.

Дано:

```text
42% и 30%
```

Ученик:

```text
The difference is 22 percentage points.
```

→ К1.

Правильно:

```text
12 percentage points.
```

---

# 15. АРИФМЕТИКА

Всегда перепроверять вычисления.

## Percentage points

```text
42% - 30% = 12 percentage points.
```

## Twice as many

Использовать только если отношение действительно ≈2.

```text
40% / 20% = 2
```

## Five times as popular

Проверять реальное отношение.

```text
29 / 6 ≈ 4.83
```

`almost five times` допустимо.

Не объявлять фактической ошибкой корректное приблизительное сравнение с маркером:

- almost;
- approximately;
- nearly;
- about.

---

# 16. СМЫСЛ ГЛАГОЛА ПРИ ОПИСАНИИ ОПРОСА

Не требовать механически только:

```text
choose
opt for
select
```

Проверять смысл конкретного survey question.

`prefer` может быть правильным, если содержание опроса действительно описывает предпочтение.

Нельзя объявлять `prefer` ошибкой автоматически.

Ошибка возникает, только если выбранный глагол действительно искажает вопрос или вариант ответа.

---

# 17. К1 — АСПЕКТ 3: СРАВНЕНИЕ

Необходимо:

A. сравнить данные;
B. прокомментировать сравнение.

## Сравнение

Должен существовать явный comparison relation.

Допустимо:

```text
higher than
lower than
more popular than
less popular than
while
whereas
compared with
twice as many
the difference is ...
the most / the least
```

Просто:

```text
40% choose A.
20% choose B.
```

без выраженной связи не является полноценным сравнением.

---

# 18. КОММЕНТАРИЙ К СРАВНЕНИЮ

Комментарий должен интерпретировать данные.

Не засчитывать:

```text
It is interesting.
```

как содержательный комментарий.

Допустимо:

```text
This may suggest that teenagers prefer activities which allow them to socialise.
```

Если комментарий является предположением, полезны:

```text
may
might
possibly
probably
This may indicate...
```

Не выдавать гипотезу за факт исследования.

---

# 19. К1 — АСПЕКТ 4: ПРОБЛЕМА + РЕШЕНИЕ

Проверить три элемента:

1. сформулирована конкретная проблема;
2. предложено решение;
3. решение действительно связано с проблемой.

Плохо:

```text
There are some problems.
```

Проблема не названа.

Хорошо:

```text
One problem is that teenagers may spend too much time online and become less physically active.
```

---

# 20. РЕШЕНИЕ ПРОБЛЕМЫ

Решение должно быть:

- конкретным;
- реалистичным;
- связанным с проблемой;
- доступным человеку / ученику / семье / школе, если контекст это позволяет.

HOUSE RULE:

избегать пустого:

```text
The government should solve this problem.
```

если предложение не конкретизировано.

Проблема:

> подросткам не хватает времени на спорт.

Слабое решение:

> они должны купить спортивное оборудование.

Это не решает проблему времени.

---

# 21. К1 — АСПЕКТ 5: МНЕНИЕ

Нужно:

1. эксплицитное мнение;
2. прямой ответ на вопрос задания;
3. объяснение.

Opinion marker:

```text
I think
I believe
In my opinion
To my mind
As for me
```

Сам маркер не закрывает аспект.

Если вопрос:

> What is the best way to spend free time?

Фраза:

```text
In my opinion, free time is important.
```

не отвечает на вопрос.

---

# 22. К1 — СТИЛЬ

Ожидается нейтральный регистр.

HOUSE STYLE VIOLATIONS:

- contractions;
- slang;
- chat abbreviations;
- rhetorical questions;
- слишком разговорное обращение к читателю;
- And / But в начале абзаца;
- Because в начале предложения;
- явно разговорные fillers.

Не считать нарушением нейтрального стиля просто конструкцию, которая агенту кажется «не очень красивой».

---

# 23. К1 — ШКАЛА

## 3/3

Коммуникативная задача выполнена полностью.

Допустимо:

- 1 аспект раскрыт неполно/неточно;
- максимум 1 нарушение нейтрального стиля.

## 2/3

Например:

- 1 аспект MISSING, остальные FULL;
- 1 MISSING + 1 PARTIAL;
- 2–3 PARTIAL;
- 2–3 стилевых нарушения.

## 1/3

Например:

- 1 MISSING + 2–3 PARTIAL;
- 2 MISSING;
- 2 MISSING + 1 PARTIAL;
- 4–5 PARTIAL;
- до 4 стилевых нарушений.

## 0/3

Все остальные случаи.

Если:

```text
K1 = 0
```

то автоматически:

```text
K2 = 0
K3 = 0
K4 = 0
K5 = 0

TOTAL = 0/14
```

Не продолжать формальное выставление ненулевых критериев.

# 25. ЭТАП 3 — К2

# К2 — Организация текста

Максимум: **3 балла**.

Проверять:

- логичность;
- соответствие плану;
- абзацы;
- переходы между частями;
- логические связки;
- референты;
- согласованность изложения.

---

# 26. АБЗАЦЫ

Для образцового ответа предпочтительны 5 абзацев:

1. проект;
2. факты;
3. сравнение;
4. проблема + решение;
5. мнение.

Но при ПРОВЕРКЕ:

не снижать автоматически только потому, что физически получилось 4 или 6 абзацев.

Сначала установить:

- соблюдён ли план;
- логично ли разделены смысловые части.

Ошибка возникает, если абзацное членение мешает структуре или отсутствует.

---

# 27. ОБЯЗАТЕЛЬНЫЕ ПЕРЕХОДЫ

Особенно проверить переходы:

```text
вступление → факты
факты → сравнение
сравнение → проблема
проблема → заключение
```

Наличие linker само по себе не даёт балл.

Он должен быть логически правильным.

---

# 28. ОШИБКИ В LINKERS = К2

Например:

```text
However
```

без противопоставления.

```text
Therefore
```

без причинно-следственной связи.

```text
In the one hand
```

вместо:

```text
On the one hand
```

→ К2.

---

# 29. HOUSE OVERRIDE ДЛЯ ОТДЕЛЬНЫХ LINKERS

По локальным правилам данного skill:

```text
to my opinion
```

вместо:

```text
in my opinion
```

если проблема рассматривается именно как ошибочное оформление формулы-маркера, учитывать в К5.

Не дублировать её затем в К4.

---

# 30. К2 — ЛОГИЧЕСКИЕ ОШИБКИ

Относить к К2:

- противоречие между предложениями;
- нелогичный вывод;
- непонятный reference;
- `this/it/they` без понятного antecedent;
- скачок `we → you`;
- `a person → he`, если пол не задан;
- логически неоправданную смену лица;
- «рубленый» фрагмент, разрушающий связь;
- ошибочную логическую связку;
- несогласованное описание одних и тех же данных.

HOUSE RULE:

необоснованная смена времён при описании статистики:

```text
respondents choose...
teenagers preferred...
```

→ К2.

---

# 31. ПРОЦЕНТЫ СЛОВАМИ

В статистической части HOUSE RULE требует проценты цифрами.

Предпочтительно:

```text
37%
```

а не:

```text
thirty-seven percent
```

При нарушении учитывать как ошибку организации / оформления данных в К2 согласно локальной экспертной схеме.

Не считать дополнительно в К5.

---

# 32. К2 — ШКАЛА

## 3/3

Текст:

- логичен;
- структура соответствует плану;
- абзацы корректны;
- связи корректны.

## 2/3

Допускаются:

**1–3 ошибки организации текста.**

## 1/3

**4–5 ошибок**

И/ИЛИ:

- отсутствует вступление;
- отсутствует заключение.

## 0/3

**6+ ошибок**

И/ИЛИ:

- отсутствуют и вступление, и заключение;
- план полностью не соблюдается;
- отсутствует деление на абзацы.

# 33. ЭТАП 4 — К3

# К3 — Лексика

Максимум: **3 балла**.

Оценивается не только количество ошибок, но и соответствие словарного запаса высокому уровню задания.

---

# 34. ЧТО ОТНОСИТСЯ К К3

## Неверное слово

```text
discussion
```

вместо:

```text
survey
```

если меняется значение.

## Collocation

```text
do the bed
```

вместо:

```text
make the bed
```

## Lexical omission

Пропущено необходимое смысловое слово, но подлежащее и сказуемое существуют.

## Word formation без смены части речи

```text
unregular
```

вместо:

```text
irregular
```

## Phrasal verb particle

Неверный particle/послелог → К3.

## Реальное другое слово

```text
lose → loose
their → there
think → thing
```

→ К3, если получается другое существующее слово и меняется смысл.

---

# 35. THE OPTION

Не требовать `the option` механически в каждом предложении.

Если ученик прямо вводит option как название ответа:

```text
the option ‘Watching films’
```

конструкция корректна.

Но если ученик естественно перефразирует:

```text
42% of the respondents prefer watching films.
```

и это соответствует смыслу опроса, отсутствие `the option` само по себе НЕ является ошибкой.

Фиксировать lexical omission только если без head noun конструкция действительно становится ненормативной или неясной.

---

# 36. К3 — ПОВТОРЯЮЩИЕСЯ ОШИБКИ

Ошибки одного и того же типа / правила считаются как одна.

Например, один и тот же ошибочный lexical pattern повторён трижды:

```text
count_for_score = 1
```

Но в разборе можно показать все instances.

---

# 37. К3 — ШКАЛА

## 3/3

- словарь соответствует высокому уровню;
- 0–1 лексическая ошибка.

## 2/3

- 2–3 лексические ошибки;

ИЛИ:

- словарь ограничен, но используется правильно.

## 1/3

- словарь не вполне соответствует высокому уровню;
- 4 ошибки.

## 0/3

- словарь не соответствует требуемому уровню;
- 5+ ошибок.

# 42. ПРОПУЩЕННЫЙ CORE ELEMENT


пропущено `is`.

→ К4.

# 43. АРТИКЛИ

Артиклевые ошибки → К4.

Особенно проверить конкретную группу опрошенных.

```text
the respondents
the teenagers
```

обычно требуется определённый артикль.

Но не применять это механически к любому слову `teenagers`.

Сначала определить reference.

# 44. ПОВТОР ОДНОГО ГРАММАТИЧЕСКОГО ПРАВИЛА

Например:

```text
he choose
she prefer
it show
```

Все три — отсутствие `-s` в Present Simple.

Это:

```text
1 грамматическая ошибка-тема
```

а не 3.

В разборе:

```text
Third-person singular -s — 3 instances, считается как 1 ошибка.
```

## 3/3

- грамматический диапазон соответствует уровню;

## 2/3

- 3–4 ошибки.

## 1/3

- 5–7 ошибок.

## 0/3

- 8+ ошибок.

По шкале это 2.

# К5 — Орфография и пунктуация

Максимум: **2 балла**.

# 47. ОРФОГРАФИЯ

К5:

- spelling;
- неправильная заглавная/строчная буква;
- маленькая буква в начале предложения;
- необоснованная capital letter внутри предложения.

Пример:

```text
definatly
```

→ К5.

Но:

```text
loose
```

вместо:

```text
lose
```

если `loose` является другим существующим словом:

→ К3.

---

# 48. ПУНКТУАЦИЯ

Проверять:

- точки;
- запятые;
- запятые после вводных элементов;
- перечисления;
- paired punctuation;
- quotation marks.

Например:

```text
However teenagers...
```

→ отсутствует запятая.

```text
In my opinion teenagers...
```

→ отсутствует запятая.

---

# 49. КАВЫЧКИ ПРИ OPTIONS

Если option прямо цитируется как название пункта:

```text
the option ‘Watching films’
```

кавычки нужны.

Если прямое цитирование оформлено без кавычек:

```text
the most popular response is To make new friends
```

→ пунктуационная ошибка.

Если перефразировано:

```text
Most respondents say that they want to make new friends.
```

кавычки не нужны.

Не снижать только за тип кавычек:

```text
‘ ’
“ ”
" "
```

если функция цитирования ясна.

Если кавычка открыта и не закрыта:

→ К5.

Строчная буква внутри корректно оформленной цитируемой option сама по себе не должна автоматически считаться ошибкой.

---

# 50. ПОВТОРЯЮЩИЕСЯ К5

Одна и та же орфографическая или пунктуационная ошибка, повторённая несколько раз по одному правилу, считается одной error topic.

---

# 51. К5 — ШКАЛА ЭТОГО SKILL

Использовать комбинацию официальной шкалы и HOUSE STRICT RULE.

## 2/2

Не более **1 ошибки суммарно**:

```text
spelling + punctuation <= 1
```

## 1/2

**2–4 ошибки**.

## 0/2

**5+ ошибок**.

Нельзя:

> 1 ошибка → 1/2.

При одной ошибке этот skill обязан поставить:

```text
К5 = 2/2
```

---

# 52. ЕСЛИ АСПЕКТ К1 НЕ ЗАСЧИТАН

Важно:

если конкретный абзац или аспект не принят по К1, это НЕ означает, что его языковые ошибки нужно игнорировать.

Например:

проблема не соответствует заданию → ошибка К1.

При этом:

```text
must to do
```

в том же абзаце всё равно учитывается в К4.

Исключение:

текст после границы 250 слов при превышении объёма.

Он вообще не проверяется.

---

# 53. НЕ СЧИТАТЬ ОШИБКОЙ

Запрещено снижать за:

- корректный British English;
- корректный American English;
- нормативный вариант, который агент лично не предпочитает;
- отсутствие «красивого» слова;
- отсутствие конкретного шаблона;
- корректный paraphrase;
- отсутствие `the option`, если предложение нормативно;
- двойные кавычки вместо одинарных;
- 4 или 6 абзацев только из-за их числа, если структура плана сохранена.

# 68. ТИПИЧНЫЕ ЛОВУШКИ, КОТОРЫЕ HERMES ДОЛЖЕН ИЗБЕГАТЬ

## Ловушка 6

ЗАПРЕЩЕНО.

## Ловушка 7

Hermes требует:

```text
In conclusion
```

как единственно допустимый conclusion linker.

ЗАПРЕЩЕНО.

Другой нормативный переход допустим, если он выполняет нужную логическую функцию.

## Ловушка 8

Hermes считает `At the end` ошибкой автоматически.

Сначала проверить смысл.

Если автор буквально имеет в виду «в конце процесса», expression может быть правильным.

Если используется как formula for essay conclusion и звучит нелогично в контексте, тогда фиксировать проблему.

## Ловушка 9

Hermes требует два аргумента в заключении.

ЗАПРЕЩЕНО, если план требует лишь мнение и объяснение.

Одного полноценного объяснения достаточно.

## Ловушка 10

Hermes считает любую фразу `government should...` автоматической ошибкой.

ЗАПРЕЩЕНО.

HOUSE RULE лишь рекомендует grounded solution.

Если государственное решение:

- конкретно;
- реалистично;
- логично;
- действительно решает проблему,

не объявлять его ошибкой только из-за субъекта.

# 70. ФИНАЛЬНАЯ SELF-CHECK ПЕРЕД ОТВЕТОМ

Hermes обязан проверить:

```text
[ ] Сначала ли я посчитал слова?
[ ] Проверяю ли только допустимый объём?
[ ] Есть ли у меня исходное задание для окончательного К1?
[ ] Проверил ли я каждую цифру?
[ ] Проверил ли я arithmetic comparisons?
[ ] Не придумал ли я ошибку?
[ ] Каждая ошибка подтверждена цитатой?
[ ] Не посчитал ли я одно правило несколько раз?
[ ] Не наказал ли одну ошибку дважды?
[ ] Соответствует ли K3 количеству lexical errors?
[ ] Соответствует ли K4 количеству grammar errors?
[ ] Соответствует ли K5 количеству spelling/punctuation errors?
[ ] Если K1=0, поставил ли я 0 всему заданию?
[ ] Не учитывал ли я текст после word limit?
[ ] Есть ли короткий пункт 4 «Итог»?
[ ] Есть ли пункт 5 «Что нужно сделать»?
[ ] Использовал ли я ✔️?
[ ] Завершается ли ответ фразой «Если хотите, могу...»?
```

Если хотя бы один критический пункт не выполнен:

ПЕРЕСМОТРЕТЬ ПРОВЕРКУ ДО ОТПРАВКИ.

# 71. ГЛАВНАЯ ФОРМУЛА НАВЫКА

> Сначала установить факты, затем классифицировать ошибки, затем посчитать уникальные ошибки по правилам, затем применить шкалу, и только после этого писать объяснение.

Не делать наоборот.

Нельзя сначала решить, что эссе «примерно на 8 баллов», а затем подбирать ошибки под желаемый результат.

Оценка должна быть следствием анализа, а не его отправной точкой.
